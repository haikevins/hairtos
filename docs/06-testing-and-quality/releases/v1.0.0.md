# hairtos v1.0.0

`v1.0.0` promotes the validated `v1.0.0-rc2` codebase to the first stable `hairtos` release. This promotion does **not** intentionally change kernel or firmware runtime behavior.

## Highlights

- Fixed-priority preemptive RTOS for the ARM Cortex-M3 reference target.
- Static-first task and kernel-object model.
- Queue, semaphore, mutex with priority inheritance, software timer, and timeout support.
- Cortex-M3 SVC/PendSV context switching.
- Diagnostics, retained fault context, and scheduler stress validation.
- `haievent` event-driven framework with Active Objects, FSMs, time events, dynamic events, and publish/subscribe.
- Reproducible GitHub Actions host validation and tag-driven release packaging.
- Portfolio-oriented README, contribution policy, security policy, and structured issue/PR templates.

## Verified host baseline

The stable release host gate covers:

- target/example registry checks;
- GCC host build with AddressSanitizer and UndefinedBehaviorSanitizer;
- `ctest`: PASS, 1/1 host test target;
- 64 host test functions in the current suite;
- example 02 host data-structure validation;
- example 14 allocator validation;
- example 16 scheduler stress validation at 500,000 iterations.

## Target hardware validation

The project owner has confirmed successful execution on the reference STM32F103C8T6 Blue Pill hardware.

The stable-release promotion changes release/version metadata and documentation only. Kernel, architecture-port, board, driver, SoC, `haievent`, test, and example runtime source remain unchanged from `v1.0.0-rc2`.

## Release assets

The tag-driven workflow publishes:

- `hairtos-1.0.0.tar.gz`
- `SHA256SUMS`

GitHub also provides its automatically generated source archives for the tag.

## Status

`hairtos` is an educational and experimental RTOS project. The `v1.0.0` tag is the first stable project release; it is not safety-certified or production-qualified for safety-critical use.
