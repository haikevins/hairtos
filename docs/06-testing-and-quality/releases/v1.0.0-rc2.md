# hairtos v1.0.0-rc2

`v1.0.0-rc2` is a release-candidate presentation and release-hygiene update for `hairtos`. It does **not** intentionally change kernel or firmware runtime behavior.

## Highlights

- Reworked the root README so the scheduler, synchronization model, Cortex-M3 port, diagnostics, `haievent`, reference target, and verification status are understandable from the repository landing page.
- Added reproducible GitHub Actions host validation.
- Added contribution, security, pull-request, and issue-reporting policies.
- Added tag-driven release packaging with a version/tag guard, release validation gate, source archive, and `SHA256SUMS`.
- Preserved the existing separation between the implemented v1 runtime (`docs/00`–`08`) and the Version 2 roadmap (`docs/09-version2`).

## Verified host baseline

The release-candidate host gate covers:

- target/example registry checks;
- GCC host build with AddressSanitizer and UndefinedBehaviorSanitizer;
- `ctest` host suite: PASS, 1/1 test target;
- 64 host test functions in the current suite;
- example 02 host data-structure validation;
- example 14 allocator validation;
- example 16 scheduler stress validation at 500,000 iterations.

## Target and hardware boundary

The host results above do **not** claim that the ARM cross-build or physical STM32F103C8T6 Blue Pill execution has been revalidated for this release candidate. Those are separate items in the project release checklist.

Because `hairtos` contains multiple target examples rather than one canonical application firmware image, this release publishes a reproducible source package and checksum file rather than presenting one `.bin`/`.hex` as a universal firmware artifact.

## Release assets

The tag workflow publishes:

- `hairtos-1.0.0-rc2.tar.gz`
- `SHA256SUMS`

GitHub also provides its automatically generated source archives for the tag.

## Status

`hairtos` remains an educational and experimental RTOS release candidate. It is not safety-certified or production-qualified.
